# Chronos — Implementation Plan

Status snapshot as of commit `46c4810` (last pushed). This file tracks what's built, what's
known broken or unverified, and what's next — a working reference for picking the project back
up, not a permanent spec.

## Stack

- Backend: .NET 10, ASP.NET Core minimal API, EF Core, MediatR, FluentValidation
- Multi-DB: SQL Server / SQLite / PostgreSQL, switched at startup via `DatabaseProvider` config
  (`Chronos.Infrastructure.DependencyInjection.AddChronosInfrastructure`)
- Frontend: Angular 22, standalone components, signals, Jest
- E2E: Playwright (scaffolded, not wired into CI yet)
- Architecture: Clean Architecture / modular monolith (Domain → Application → Infrastructure → Api)

## Done

- **Projects/Gantt**: `Project` aggregate with `GanttTask`/`TaskDependency` children, full
  CQRS vertical slice, repository, endpoint, tests at every layer. Gantt UI wraps Frappe Gantt
  (MIT) behind an `IGanttRenderer` port for testability and to keep the third-party dependency
  swappable.
- **Leave (ferie) workflow**: `LeaveRequest` aggregate (create/approve/reject/cancel), same
  full-slice treatment. Cancel enforces requester-or-Admin ownership.
- **Auth**: JWT bearer tokens, PBKDF2-SHA256 password hashing (BCL only), `User` aggregate with
  roles (Employee/Approver/Admin). Every endpoint derives organization/requester/approver
  identity from the token's claims, never from the request body. `ApproverOrAdmin` policy on
  approve/reject.
- **CI**: `.github/workflows/ci.yml`, backend matrixed over the three DB providers (Sqlite runs
  the fast suite, SqlServer/PostgreSql run their Testcontainers-backed repository tests), plus a
  frontend Jest job.
- **Frontend auth wiring**: `AuthService` (signal-based session, localStorage-persisted,
  expiry-aware), `authInterceptor`, `authGuard`, `LoginComponent`. `LeaveRequestsPageComponent`
  is routed at `/leave` behind the guard — no longer blocked on missing identity inputs.

## Known issues (not yet pushed — fixes are in the local working tree)

Found by actually running `npm install` / `npm test` for the first time in this pass (previously
only reasoned about statically, never executed):

1. **`AddValidatorsFromAssembly` doesn't compile.** It lives in
   `FluentValidation.DependencyInjectionExtensions`, not core `FluentValidation`. Fix (in
   `Chronos.Api.csproj`, uncommitted) is a one-line package reference add. **The .NET build has
   still never actually been run** — no SDK in the environment that authored this plan — so this
   fix is unverified beyond static reading of the error.
2. **Frontend dependency versions were wrong for Angular 22**: `jest-preset-angular` was pinned
   to a v14-era API incompatible with Angular ≥19; `jest`/`jest-environment-jsdom` needed bumping
   to v30 to match; `ts-jest`, `esbuild-register`, and a pinned `jsdom` were missing entirely.
   Fixed by matching the versions and `jest.config.ts`/`setup-jest.ts` shape from
   `jest-preset-angular`'s own official `example-app-v22` (verified live against the npm
   registry and GitHub, not assumed).
3. **`angular.json` was missing `"polyfills": ["zone.js"]`.** Without it the app would not have
   booted in a real browser at all — zone.js was a dependency but never actually loaded. Real bug
   in the original scaffold, not just a test-config issue.
4. **`frappe-gantt` has no TypeScript types and ships ESM-only.** Needed: an ambient module
   declaration (`src/types.d.ts`), a local interface instead of using the untyped default import
   as a type, and `transformIgnorePatterns`/`moduleNameMapper` adjustments in `jest.config.ts` so
   Jest can load its ESM `.js` and stub its internal `.scss` import. First attempt at the
   `transformIgnorePatterns` fix *replaced* the preset's own pattern instead of extending it,
   which broke every test by making `@angular/core` itself unloadable — worth remembering if this
   surfaces again.
5. **One test still failing**: `gantt-chart.component.spec.ts` — the "delegates to updateTasks on
   subsequent changes" case gets `null` instead of the expected updated task list. Root cause not
   yet found; suspect the `effect()` in `GanttChartComponent` isn't re-running when the test
   reassigns the `tasks` input, or the test's reassignment pattern is itself wrong. Needs
   investigation, not yet attempted.
6. **`package-lock.json` now exists** (generated by the real `npm install` above, 627 packages,
   0 vulnerabilities) but is untracked/uncommitted. Once the remaining test is fixed, commit it
   and switch CI from `npm install` to `npm ci` for reproducible installs.

None of the above six items are reflected in the pushed repo yet — they exist only in this
session's local working tree.

## Not started

- **CI for the frontend fixes above** — the pushed `ci.yml` will currently fail the same way
  local `npm test` did before these fixes; needs a fresh CI run once the fixes are committed.
- **E2E in CI**: needs the API + a database running alongside the frontend dev server, more
  orchestration than covered so far; currently documented as a manual/local-only step.
- **Cross-org Admin visibility** for leave requests (currently every user, Admin included, only
  ever sees their own organization).
- **Refresh-token flow** on the frontend (an expired JWT is just treated as logged out).
- **Role promotion** (Employee → Approver/Admin): no admin-only endpoint exists yet; only doable
  today by writing directly to the database.
- **`Jwt:SigningKey` in `appsettings.json` is a placeholder** — must move to user-secrets/
  environment/Key Vault before anything beyond local dev.
- **Open self-registration** into any `OrganizationId` supplied by the caller — no invite or
  verification step.
